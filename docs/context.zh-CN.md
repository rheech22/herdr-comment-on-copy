# 上下文收集

[English](context.md) · [한국어](context.ko.md) · [简体中文](context.zh-CN.md) · [日本語](context.ja.md)

消息分为 `context`、`selection` 和 `comment` 区块。上下文帮助接收消息的智能体了解选中的终端文本来自哪里，以及涉及哪个项目、程序或文件。无法获取的可选字段会被省略。

## 字段

| 字段 | 收集方式 | 用途 |
| --- | --- | --- |
| `source` | 标识 Herdr 和 Comment on Copy 的固定文本。 | 标识提供上下文的工具。 |
| `capture` | 关于选中或复制的终端文本及可获取窗格信息的固定说明。 | 说明这些信息的性质。 |
| `workspace` | 将 `pane.get` 中的工作区 ID 映射到 `workspace.list` 中的名称；没有名称时使用 ID。 | 标识工作区。 |
| `tab` | 将 `pane.get` 中的标签页 ID 映射到 `tab.list` 中的名称；没有名称时使用 ID。 | 区分工作区内的任务位置。 |
| `pane` | 与选中文本匹配的可见窗格 ID。手动打开时，若找不到匹配则使用当前聚焦窗格。 | 标识文本所在的终端。 |
| `process` | 对 `pane.process_info` 返回的前台进程名称去重并合并。 | 说明正在前台运行的程序，例如 `codex`、`hunk` 或 `zsh`。 |
| `agent` | `pane.get` 返回的 Herdr 智能体识别信息。 | 说明 Herdr 将该窗格识别为何种智能体。 |
| `title` | `pane.get` 返回的已去除控制码的终端标题。 | 补充程序提供的会话或任务名称。 |
| `cwd` | 优先使用 `pane.get` 的 `foreground_cwd`，否则使用窗格的 `cwd`；主目录缩写为 `~`。 | 提供用于理解项目和相对路径的工作目录。 |
| `branch` | 执行 `git -C <cwd> rev-parse --abbrev-ref HEAD`，超时为 150ms。 | 提供 Git 分支；分离 HEAD 状态下返回 `HEAD`。 |
| `selection` | 去除末尾换行后计算行数和 Unicode 码点数，若可确定则附加选区起始屏幕行。 | 说明选区大小及屏幕位置。 |
| `files` | 从选中文本中提取类似路径的字符串，并在需要时相对于 `cwd` 检查是否存在；最多五个。 | 列出文本明确提到的路径。 |
| `file` | 在 Git 仓库中对选中的一行进行可选的固定字符串搜索，返回相对路径和行号。 | 为没有文件名的代码片段推测文件位置。 |
| `captured_at` | 准备弹窗数据时记录的 ISO 时间；发送或复制 Collection 条目时包含。 | 区分准备收集数据的时间。 |
| `collected_at` | Collect 保存条目时的 ISO 时间；包含在 Collection 输出中。 | 区分收集与保存时间，并说明条目顺序。 |

`process` 是前台程序，`agent` 是 Herdr 对窗格的智能体分类。插件分别向 Herdr 查询，而不自行扫描系统进程列表。

`screen row` 是从 0 开始的可见终端位置，不是源文件行号。如果只能通过选区后面的行确认窗格，则不猜测起始行。找到 `file` 后会移除 `screen row`，避免混淆两种位置。

## 确认来源窗格

自动检测通过 `pane.list` 和 `pane.read` 将复制文本与窗格可见内容比较。先检查聚焦窗格，再以最多四个一组检查其他窗格。比较时容忍 Markdown 装饰、终端颜色码、空白差异和自动换行，也会使用第一行之后的有效文本。此规范化仅用于匹配，不会改写选中的内容。

没有匹配时，会在 40ms 后重新检查一次聚焦窗格；总查找时间上限为 250ms。仍无匹配则不自动打开弹窗。手动打开可以使用聚焦窗格作为后备，但这并不能证明剪贴板文本实际来自该窗格。

## 为什么搜索文件？

代码片段可能没有文件名。附上 `file: src/example.ts:42` 可以减少接收消息的智能体再次寻找代码的工作。普通终端输出通常较少受益，因此这是可选推测，在弹窗打开后执行。

`files` 只检查文本中提到的路径，不搜索文件内容，也不验证文本附带的行号。`file` 使用 Git 和可选安装的 `rg` 搜索内容：

1. 去除各行首尾空白，选择最长的一行；少于 30 个 Unicode 码点时跳过。
2. 工作目录缺失、为主目录或文件系统根目录时跳过。
3. 用 Git 查询仓库根目录及当前目录的路径前缀，最多 150ms。非 Git 仓库，或仓库根目录解析为主目录或文件系统根目录时跳过。
4. 在仓库内执行 `rg --fixed-strings --line-number --max-count 1`，遵循通常的 `rg` 忽略规则。仅接受一个结果；没有结果或多个文件匹配时省略 `file`。
5. 在该文件中尝试查找选区内第一条至少 12 个码点的行，以调整行号。失败时保留最长行的位置。
6. 返回相对于 `cwd` 的路径。所有子进程共享总计 500ms 的预算，包括 Git 查询和行号调整。

结果只是候选位置，并非整个选区来自该文件的证明。`--max-count 1` 只返回每个文件的首个匹配行，因此不会区分同一文件中的重复文本。超时、工具缺失或查询失败时只省略 `file`。若 `files` 中也有该路径，会移除重复项。

## 收集时机

弹窗先使用 `source`、`capture`、可获取的 `pane` 和 `selection` 打开。界面显示后，并行查询窗格信息、工作区与标签页名称、前台进程；随后并行获取 Git 分支和搜索文件。接收者列表独立加载，同一弹窗内的重复 API 请求会共享结果。

发送、复制和 Collect 使用执行操作时已经获取的上下文。Collect 保存上下文副本，后续后台更新或重新打开 Collection 不会用当前窗格信息覆盖它。发送或复制 Collection 条目时，会为各条目加入 `captured_at` 和 `collected_at`。

`captured_at` 是插件准备数据的时间，不是操作系统复制事件的时间。元数据在弹窗打开后查询，因此并非复制瞬间所有字段的原子快照。关闭弹窗会取消后续收集，避免延迟结果影响其他收集。

## 接收者

候选智能体来自 `agent.list`，名称使用 `workspace.list` 和 `tab.list` 补充。自动选择依次优先考虑来源窗格中的智能体、聚焦窗格中的智能体、同一标签页中的唯一智能体、同一工作区中的唯一智能体、全局唯一候选。候选不明确时需手动选择。接收者列表不会加入消息的 `context`。
