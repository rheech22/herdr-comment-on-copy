# 컨텍스트 수집

[English](context.md) · [한국어](context.ko.md) · [简体中文](context.zh-CN.md) · [日本語](context.ja.md)

메시지는 `context`, `selection`, `comment` 블록으로 구분됩니다. 컨텍스트는 선택한 터미널 텍스트가 어디에서 왔고 어떤 프로젝트·프로그램·파일과 관련 있는지 수신 에이전트에게 설명합니다. 확인할 수 없는 선택적 항목은 생략합니다.

## 항목별 수집 방식과 목적

| 항목 | 수집 방식 | 목적 |
| --- | --- | --- |
| `source` | Herdr와 Comment on Copy를 나타내는 고정 문구입니다. | 컨텍스트를 제공한 도구를 식별합니다. |
| `capture` | 선택·복사한 터미널 텍스트와 확인 가능한 페인 정보라는 고정 설명입니다. | 수집된 정보의 성격을 설명합니다. |
| `workspace` | `pane.get`의 워크스페이스 ID를 `workspace.list`의 이름과 연결합니다. 이름이 없으면 ID를 사용합니다. | 작업 공간을 식별합니다. |
| `tab` | `pane.get`의 탭 ID를 `tab.list`의 이름과 연결합니다. 이름이 없으면 ID를 사용합니다. | 워크스페이스 안의 작업 위치를 구분합니다. |
| `pane` | 선택한 텍스트와 화면 내용이 일치하는 페인의 ID입니다. 수동 열기에서는 일치하는 페인을 찾지 못하면 포커스된 페인을 사용합니다. | 내용이 나온 터미널을 식별합니다. |
| `process` | `pane.process_info`가 반환한 전경 프로세스 이름을 중복 제거해 함께 표시합니다. | `codex`, `hunk`, `zsh` 등 전경에서 실행 중인 프로그램을 설명합니다. |
| `agent` | `pane.get`의 에이전트 감지 정보입니다. | Herdr가 해당 페인을 어떤 에이전트로 인식하는지 설명합니다. |
| `title` | `pane.get`이 반환한 제어 코드가 제거된 터미널 제목입니다. | 프로그램이 제공하는 세션명이나 작업 제목을 보충합니다. |
| `cwd` | `pane.get`의 `foreground_cwd`를 우선 사용하고, 없으면 페인의 `cwd`를 사용합니다. 홈 경로는 `~`로 줄입니다. | 프로젝트와 상대 경로를 해석할 작업 경로를 제공합니다. |
| `branch` | `git -C <cwd> rev-parse --abbrev-ref HEAD`를 최대 150ms 동안 실행합니다. | Git 브랜치를 전달합니다. Detached HEAD에서는 `HEAD`가 표시됩니다. |
| `selection` | 끝의 개행을 제거한 원문에서 줄 수와 Unicode 코드 포인트 수를 계산합니다. 확인된 경우 선택 시작 화면 행도 표시합니다. | 선택 범위의 크기와 화면 위치를 설명합니다. |
| `files` | 원문에서 경로처럼 보이는 문자열을 추출하고, 필요하면 `cwd` 기준으로 존재 여부를 확인합니다. 최대 5개입니다. | 원문에 명시적으로 등장하는 경로를 전달합니다. |
| `file` | 선택한 한 줄을 Git 저장소에서 문자열 그대로 검색해 상대 경로와 줄 번호를 추정합니다. | 파일명이 없는 코드 조각의 출처를 보충합니다. |
| `captured_at` | 팝업용 데이터를 준비할 때 기록한 ISO 시각입니다. Collection 항목을 전송·복사할 때 포함합니다. | 수집을 준비한 시점을 구분합니다. |
| `collected_at` | Collect로 저장한 ISO 시각입니다. Collection 결과에 포함합니다. | 수집과 저장 시점을 구분하고 항목 순서를 설명합니다. |

`process`는 전경 프로그램이고, `agent`는 Herdr의 에이전트 분류입니다. 플러그인이 시스템 전체 프로세스를 직접 탐색하는 대신 Herdr에 각각 조회합니다.

`screen row`는 0부터 시작하는 터미널 화면 위치이며 소스 파일의 줄 번호가 아닙니다. 선택의 뒷부분으로만 페인을 확인했다면 시작 행을 추측하지 않고 생략합니다. `file`을 찾으면 두 위치의 혼동을 피하려고 `screen row`를 제거합니다.

## 출처 페인 확인

자동 감지는 `pane.list`와 `pane.read`로 복사한 텍스트를 페인에 보이는 내용과 비교합니다. 포커스된 페인을 먼저 확인하고 다른 페인은 최대 4개씩 함께 확인합니다. Markdown 장식, 터미널 색상 코드, 공백 차이, 자동 줄바꿈을 정리해 비교하며 첫 줄 외의 의미 있는 줄도 사용합니다. 이 정리는 비교에만 적용하고 선택한 내용을 다시 쓰지 않습니다.

찾지 못하면 40ms 뒤 포커스된 페인을 한 번 더 확인하며, 전체 탐색은 최대 250ms입니다. 끝내 일치하는 페인이 없으면 자동 팝업을 열지 않습니다. 수동 열기는 포커스된 페인을 대신 사용할 수 있지만, 이 경우 클립보드 원문의 실제 출처가 확인된 것은 아닙니다.

## 파일을 검색하는 이유

파일명이 없는 코드 조각에 `file: src/example.ts:42`를 붙이면 수신 에이전트가 코드를 다시 찾는 수고를 줄일 수 있습니다. 일반적인 터미널 출력에서는 효과가 작으므로 선택적인 추론이며, 팝업이 열린 뒤에 수행합니다.

`files`는 원문에 등장하는 경로만 확인합니다. 파일 내용을 검색하거나 원문에 적힌 줄 번호를 검증하지 않습니다. `file`은 Git과 선택적으로 설치하는 `rg`를 사용해 내용을 검색합니다.

1. 각 줄의 앞뒤 공백을 제거하고 가장 긴 줄을 고릅니다. 30 코드 포인트 미만이면 건너뜁니다.
2. 작업 경로가 없거나 홈 디렉터리·파일시스템 루트이면 건너뜁니다.
3. Git으로 저장소 루트와 현재 경로의 접두 경로를 최대 150ms 동안 확인합니다. Git 저장소가 아니거나 저장소 루트가 홈·파일시스템 루트로 해석되면 건너뜁니다.
4. 저장소 안에서 `rg --fixed-strings --line-number --max-count 1`로 검색합니다. 기본 `rg` 제외 규칙을 따릅니다. 결과가 정확히 하나일 때만 사용하며, 결과가 없거나 여러 파일에서 발견되면 `file`을 생략합니다.
5. 해당 파일에서 선택한 줄 중 처음으로 12 코드 포인트 이상인 줄을 찾아 줄 번호를 보정합니다. 찾지 못하면 가장 긴 줄의 위치를 유지합니다.
6. `cwd` 기준 상대 경로를 기록합니다. Git 조회와 줄 번호 보정을 포함한 모든 하위 프로세스가 총 500ms 제한을 공유합니다.

이 결과는 출처 후보이며 전체 선택 내용이 그 파일에서 왔다는 증명은 아닙니다. `--max-count 1`은 파일마다 첫 일치 행을 반환하므로 한 파일 안에 같은 문장이 반복되는 경우까지 구분하지 않습니다. 시간 초과·도구 부재·검색 실패 시 `file`만 생략합니다. `file`에 표시한 경로가 `files`에도 있다면 중복을 제거합니다.

## 수집 시점

팝업은 `source`, `capture`, 확인 가능한 `pane`, `selection`을 먼저 준비해 열립니다. UI가 표시된 뒤 페인 정보, 워크스페이스·탭 이름, 전경 프로세스를 병렬로 조회합니다. 이후 Git 브랜치와 파일 검색도 병렬로 수행합니다. 전송 대상 에이전트 목록은 이 컨텍스트 수집과 독립적으로 가져오며, 동일한 API 요청은 해당 팝업 안에서만 공유합니다.

전송·복사·Collect는 액션 시점까지 준비된 컨텍스트를 사용합니다. Collect는 그 컨텍스트의 복사본을 저장하므로 이후의 비동기 갱신이나 Collection 재열기가 현재 페인 정보로 덮어쓰지 않습니다. Collection 항목을 전송·복사할 때 각 항목에 `captured_at`과 `collected_at`을 추가합니다.

`captured_at`은 플러그인의 준비 시각이며 OS 복사 이벤트의 시각이 아닙니다. 메타데이터도 팝업을 연 뒤 조회하므로 모든 항목을 복사 순간에 원자적으로 고정한 스냅샷은 아닙니다. 팝업을 닫으면 진행 중인 추가 수집을 취소하고 늦게 도착한 결과가 다른 수집에 섞이지 않도록 합니다.

## 전송 대상

후보 에이전트는 `agent.list`에서 가져오고 `workspace.list`, `tab.list`로 이름을 붙입니다. 자동 선택은 출처 페인의 에이전트, 포커스된 페인의 에이전트, 같은 탭의 유일한 에이전트, 같은 워크스페이스의 유일한 에이전트, 전체의 유일한 에이전트 순서로 확인합니다. 후보가 모호하면 직접 선택해야 합니다. 후보 목록 자체는 메시지의 `context`에 넣지 않습니다.
