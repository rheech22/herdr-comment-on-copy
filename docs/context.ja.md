# コンテキストの収集

[English](context.md) · [한국어](context.ko.md) · [简体中文](context.zh-CN.md) · [日本語](context.ja.md)

メッセージは `context`、`selection`、`comment` のブロックに分かれます。コンテキストは、選択したターミナルのテキストの出所と、関連するプロジェクト・プログラム・ファイルを受信側のエージェントに伝えます。取得できない任意項目は省略します。

## 項目

| 項目 | 収集方法 | 目的 |
| --- | --- | --- |
| `source` | Herdr と Comment on Copy を示す固定文です。 | コンテキストを提供したツールを識別します。 |
| `capture` | 選択・コピーしたターミナルのテキストと取得可能なペイン情報についての固定説明です。 | 収集された情報の性質を説明します。 |
| `workspace` | `pane.get` のワークスペース ID を `workspace.list` の名前と対応付けます。名前がなければ ID を使います。 | ワークスペースを識別します。 |
| `tab` | `pane.get` のタブ ID を `tab.list` の名前と対応付けます。名前がなければ ID を使います。 | ワークスペース内の作業場所を区別します。 |
| `pane` | 選択テキストと表示内容が一致するペインの ID です。手動で開く場合、一致しなければフォーカス中のペインを使います。 | テキストが表示されていたターミナルを識別します。 |
| `process` | `pane.process_info` が返すフォアグラウンドのプロセス名を重複除去してまとめます。 | `codex`、`hunk`、`zsh` など実行中のプログラムを説明します。 |
| `agent` | `pane.get` が返す Herdr のエージェント検出情報です。 | Herdr がペインをどのエージェントとして認識しているかを示します。 |
| `title` | `pane.get` が返す制御コードを除去したターミナルのタイトルです。 | プログラムが提供するセッション名や作業名を補足します。 |
| `cwd` | `pane.get` の `foreground_cwd` を優先し、なければペインの `cwd` を使います。ホームは `~` に短縮します。 | プロジェクトと相対パスを解釈する作業ディレクトリを提供します。 |
| `branch` | `git -C <cwd> rev-parse --abbrev-ref HEAD` を最大 150ms 実行します。 | Git ブランチを示します。Detached HEAD では `HEAD` になります。 |
| `selection` | 末尾の改行を除いた原文から行数と Unicode コードポイント数を計算し、確認できれば選択開始位置の画面行も付けます。 | 選択範囲の大きさと画面位置を説明します。 |
| `files` | 選択内容からパスらしい文字列を抽出し、必要に応じて `cwd` 基準で存在を確認します。最大五つです。 | 原文に明示されているパスを列挙します。 |
| `file` | Git リポジトリで選択した一行を固定文字列検索し、相対パスと行番号を推定します。 | ファイル名のないコード片にファイル位置を補足します。 |
| `captured_at` | ポップアップ用データの準備時に記録する ISO 時刻です。Collection 項目の送信・コピー時に含めます。 | 収集を準備した時点を区別します。 |
| `collected_at` | Collect で保存した ISO 時刻です。Collection の出力に含めます。 | 収集と保存の時点を区別し、項目の順序を説明します。 |

`process` はフォアグラウンドのプログラム、`agent` は Herdr によるエージェント分類です。プラグイン自身でシステム全体のプロセスを検索せず、それぞれ Herdr に問い合わせます。

`screen row` は 0 から始まる可視ターミナル上の位置で、ソースファイルの行番号ではありません。選択の途中の行だけでペインを確認できた場合、開始行は推測せず省略します。`file` が見つかれば、二つの位置を混同しないよう `screen row` を削除します。

## 出所のペインを確認する方法

自動検出は `pane.list` と `pane.read` で、コピーしたテキストをペインの表示内容と比較します。フォーカス中のペインを先に調べ、他は最大四つずつ調べます。Markdown の装飾、ターミナルの色コード、空白の違い、自動折り返しを考慮し、最初の行以外の意味のある行も使います。この正規化は照合だけに使い、選択内容を書き換えません。

見つからなければ 40ms 後にフォーカス中のペインを一度だけ再確認し、探索全体は最大 250ms です。一致するペインがなければ自動ポップアップを開きません。手動で開く場合はフォーカス中のペインを代わりに使えますが、それだけではクリップボードの実際の出所を確認したことにはなりません。

## ファイルを検索する理由

コード片にはファイル名がないことがあります。`file: src/example.ts:42` を添えると、受信側のエージェントがコードを再検索する手間を減らせます。通常のターミナル出力では効果が小さいため、任意の推定としてポップアップを開いた後に行います。

`files` は選択内容に現れるパスの存在だけを確認します。ファイル内容の検索や、記載された行番号の検証はしません。`file` は Git と任意でインストールする `rg` を使って内容を検索します。

1. 各行の前後の空白を除去して最長行を選びます。30 Unicode コードポイント未満なら省略します。
2. 作業ディレクトリがない場合、ホームまたはファイルシステムのルートの場合は省略します。
3. Git でリポジトリのルートと現在位置のパス接頭辞を最大 150ms 調べます。Git リポジトリでない場合や、ルートがホームまたはファイルシステムのルートに解決される場合は省略します。
4. リポジトリ内で `rg --fixed-strings --line-number --max-count 1` を実行します。通常の `rg` 除外規則に従います。結果が一つのときだけ使い、結果がない場合や複数ファイルに一致する場合は `file` を省略します。
5. そのファイルで、選択中の最初の 12 コードポイント以上の行を探して行番号を調整します。見つからなければ最長行の位置を使います。
6. `cwd` 基準の相対パスを返します。Git の確認と行番号の調整を含む全サブプロセスが、合計 500ms の制限を共有します。

結果は候補位置であり、選択全体がそのファイルから来たという証明ではありません。`--max-count 1` は各ファイルの最初の一致行を返すため、同じファイル内の繰り返しは区別しません。タイムアウト、ツール不足、検索失敗時は `file` だけを省略します。`files` にも同じパスがあれば重複を除去します。

## 収集する時点

ポップアップは `source`、`capture`、取得可能な `pane`、`selection` を先に用意して開きます。UI 表示後、ペイン情報、ワークスペース・タブ名、フォアグラウンドのプロセスを並列で取得します。その後、Git ブランチとファイル検索を並列に実行します。送信先エージェントの一覧は独立して取得し、同一 API リクエストはそのポップアップ内だけで共有します。

送信・コピー・Collect は操作時点までに取得したコンテキストを使います。Collect はそのコピーを保存するため、後から届く情報や Collection の再表示で現在のペイン情報に置き換わりません。Collection 項目の送信・コピー時に、各項目へ `captured_at` と `collected_at` を追加します。

`captured_at` はプラグインの準備時刻で、OS のコピーイベント時刻ではありません。メタデータもポップアップ表示後に問い合わせるため、コピー瞬間の全情報を一括固定したスナップショットではありません。閉じると追加収集をキャンセルし、遅れて届く結果が別の収集に混ざることを防ぎます。

## 送信先

候補は `agent.list` から取得し、`workspace.list` と `tab.list` で名前を補足します。自動選択は、出所ペインのエージェント、フォーカス中のペインのエージェント、同じタブの唯一のエージェント、同じワークスペースの唯一のエージェント、全体の唯一の候補の順に確認します。曖昧な場合は選択が必要です。候補一覧自体はメッセージの `context` に含めません。
